# Q.Sock

Кросс-платформенный мессенджер: ASP.NET Core, SignalR, EF Core / SQLite и Avalonia. Браузерный клиент тоже использует Avalonia через WebAssembly. WebRTC работает через небольшой JavaScript-мост к браузерным средствам связи.

На выходе три продукта: обычный сервер со встроенным браузерным клиентом и поддержкой расширений; один универсальный клиент для компьютера и Android; Moodle-пакет с тем же встроенным сервером, браузерным клиентом и учебными расширениями. Базовый экран входа запрашивает адрес сервера, логин и пароль. Учебные действия поступают только из загруженного расширения.

## Структура

| Проект | Назначение |
| --- | --- |
| Q.Sock.Shared | Общие контракты API |
| Q.Sock.Core | Подключение, авторизация, SignalR, темы, Markdown, проверка пакетов |
| Q.Sock.UI | Общий адаптивный интерфейс |
| Q.Sock.PluginContracts | Контракт загружаемых модулей интерфейса |
| Q.Sock.Client | Настольный клиент |
| Q.Sock.Android | Android-клиент, защищённое хранение сессий |
| Q.Sock.Browser | Браузерный хост общего интерфейса |
| Q.Sock.Plugins.Moodle | Отдельный модуль интерфейса занятий |
| Q.Sock.Browser/wwwroot | JavaScript для запуска клиента в браузере и WebRTC |
| Q.Sock.Server | Универсальный сервер и загрузчик серверных расширений |
| Q.Sock.Server.Plugins.Moodle | Вход через Moodle, синхронизация курсов, занятия и отдельный контекст данных |
| integrations/moodle | Локальный плагин Moodle и элемент курса |
| Tools/ModulePack | Упаковка и подпись клиентских модулей |
| Tests | Проверки клиента, сервера и интеграции с Moodle |

Модули интерфейса скачиваются с выбранного сервера и кэшируются отдельно от клиента. Первый запуск требует доверия к ключу издателя. Клиент проверяет хеш DLL и подпись издателя перед запуском модуля. Для подписи модуля Moodle используется [`build/Build-MoodlePlugin.ps1`](build/Build-MoodlePlugin.ps1).

## Возможности текущей версии

Личные и групповые чаты, пространства с каналами и голосовыми комнатами, друзья и поиск пользователей, вложения и просмотр исходного кода, Markdown. Material Icons используются только в интерфейсе; преобразование смайликов и коротких кодов в сообщениях отключено. Аватарки без фотографии получают стабильный цвет из палитры 32 оттенков по ID и типу сущности. Личный чат уникален для пары пользователей; выбор получателей звонка появляется в групповых чатах. В голосовую комнату входят без рассылки вызова.

Роли, локальные ограничения сообщений, голоса, подключения и демонстрации экрана, завершение сессий устройств, политика сервера, журнал и экспорт SQLite. В учебном режиме Q.Sock подключается к учебному сайту на Moodle. Состав участников, роли и группы берутся из курса. Преподаватель может запланировать занятие, а участники могут открыть его из курса или календаря.

Темы хранятся локально, редактируются, импортируются из файла или изображения QR и экспортируются в файл / QR. Сканирование QR камерой реализовано в браузере при наличии BarcodeDetector; в остальных случаях используется изображение. Разные серверы и аккаунты доступны в настольном и Android-клиентах. Браузер привязан к своему серверу.

## Локальный запуск

Нужен .NET 10 SDK. Для пересборки браузерного клиента установите `wasm-tools`. Для сборки APK нужны рабочая нагрузка `android`, Android SDK с API 36 и совместимый JDK.

Из корня репозитория:

```powershell
dotnet workload install wasm-tools
./build/Build-Browser.ps1
$env:ConnectionStrings__ChatDatabase = 'Data Source=development.db'
$env:Bootstrap__AdminUser = 'Administrator'
$env:Bootstrap__AdminPassword = 'your-local-password'
dotnet run --project Q.Sock.Server -- --urls http://127.0.0.1:5210
```

Браузер: http://127.0.0.1:5210/avalonia/index.html. Адрес `/` ведёт туда же. Во втором терминале:

```powershell
dotnet run --project Q.Sock.Client
```

В настольном клиенте введите адрес `http://127.0.0.1:5210` и созданные при запуске логин и пароль. Для подключения к серверу с Android или к удалённому серверу нужен адрес HTTPS.

При недоступном системном хранилище Windows вход продолжает работать до закрытия приложения; клиент показывает, что сеанс не сохранён. Токены остаются только в памяти. Для отдельного тестового профиля можно задать QSOCK_PROFILE_DIRECTORY; основной список аккаунтов и настройки не используются.

Скрипты сборки принимают `-Dotnet`, если нужно указать другой SDK. Браузерную сборку на Windows можно запустить с `-InProcessWasmTasks`, если обычный запуск задач WebAssembly не работает.

## Сборка и поставка

| Поставка | Команда | Результат |
| --- | --- | --- |
| Обычный сервер с браузерным клиентом | `./build/Publish-Server.ps1` | `artifacts/products/server` |
| Универсальный клиент | `./build/Publish-Client.ps1` для Windows, `dotnet build Q.Sock.Android` для Android | `artifacts/products/client` для Windows, `Q.Sock.Android/bin/Debug/net10.0-android` для отладочного APK |
| Комплект Moodle для Windows | `./build/Package-Moodle.ps1 -Runtime win-x64` | `artifacts/products/moodle` |

Android-проект собирается отдельно от `Q.Sock.slnx`. По умолчанию в проекте указаны ARM64 и x64, минимум Android 7.0 (API 24). Для отдельной сборки под ARM64 укажите `-p:RuntimeIdentifiers=android-arm64`. Если SDK и JDK не обнаруживаются, передайте `AndroidSdkDirectory` и `JavaSdkDirectory` как параметры MSBuild. Для выпуска используйте свой ключ подписи.

## Учебный сайт Moodle

1. Соберите комплект для ОС сервера. Для Linux доступны `-Runtime linux-x64` и `-Runtime linux-arm64`. Архив `local_qsock_<runtime>.zip` содержит сервер, браузерный клиент и расширения. Архив `mod_qsock_<runtime>.zip` добавляет элемент курса.
2. Установите оба архива на учебный сайт. Минимальная версия в метаданных плагина — Moodle 4.3. Включите веб-службы и REST для сервиса `qsock`, выдайте права на использование REST и создание токена. Настройте cron Moodle для синхронизации.
3. Из каталога Moodle запустите `php local/qsock/cli/server.php --public-url=https://messenger.example.edu`, указав свой адрес. По умолчанию встроенный сервер слушает `127.0.0.1:5210`. Опубликуйте его через HTTPS-прокси с WebSocket и закройте веб-доступ к `local/qsock/server`. Для проверки и остановки используйте `--status` и `--stop`.
4. Добавьте в курс элемент «Занятие Q.Sock» и выберите учебную комнату или занятие. Данные Moodle хранятся в его базе. Q.Sock хранит свою SQLite-базу, вложения и ключи отдельно, в `moodledata/local_qsock/server`.

## Настройка сервера

Дополнительную конфигурацию можно задать в `Q.Sock.Server/appsettings.Local.json`. Переменные окружения и аргументы имеют приоритет. Файл исключён из Git. Сохраняйте каталог `state` между перезапусками: в нём находятся ключи JWT и Data Protection.

Пример настройки двух учебных сайтов при установленном серверном модуле Moodle и собственных ICE-серверах. Замените адреса и секреты на свои. Для каждого сайта секрет должен совпадать с настройкой его плагина Moodle.

```json
{
  "Moodle": {
    "Enabled": true,
    "IdentityAuthority": "main-site",
    "Connections": [
      {
        "Id": "main-site",
        "Provider": "university",
        "BaseUrl": "https://moodle.example.org",
        "Secret": "replace-with-32-or-more-random-characters"
      },
      {
        "Id": "second-site",
        "Provider": "university",
        "BaseUrl": "https://moodle2.example.org",
        "Secret": "replace-with-another-random-connection-secret"
      }
    ]
  },
  "WebRtc": {
    "IceServers": [
      {
        "Urls": ["stun:turn.example.org:3478"]
      },
      {
        "Urls": ["turns:turn.example.org:5349?transport=tcp"],
        "Username": "replace-with-turn-account",
        "Credential": "replace-with-turn-password"
      }
    ]
  }
}
```

Для разных сетей настройте собственные STUN/TURN в WebRtc:IceServers. Автоматической настройки TURN нет. Медиа идёт между браузерами, сервер маршрутизирует сигналы. Текущая конфигурация ограничивает звонок 12 подключениями; для полноразмерных занятий нужен отдельный SFU и реализация соответствующего транспорта.

Экспорт админ-панели содержит SQLite-базу. Вложения и state сохраняются отдельно. Восстановление выполняется на остановленном сервере после проверки копии.

## Проверка и ограничения

Воспроизводимая проверка на новых изолированных базах:

```powershell
python Tests/run_checks.py
```

При уже собранных проектах добавьте --no-build. Параметр --dotnet позволяет указать отдельный SDK. Скрипт запускает серверы Q.Sock и тестовую HTTP-заглушку Moodle на свободных портах. Шесть наборов проверяют выдачу подписанных модулей, вход через заглушку Moodle, экспорт SQLite, подпись обратного запроса календаря и рендеринг каталога Material Icons.

Tests/serve_browser_checks.py запускает на 127.0.0.1:5213 отдельную страницу проверки WebRTC и IndexedDB. Она использует синтетические источники без камеры, микрофона, захвата экрана и звука из динамиков. После перезагрузки повторный запуск проверяет сохранение пакета в IndexedDB.

На Android и настольном клиенте звонок сейчас открывает браузерный Avalonia-экран с одноразовым входом. Нативный медиатранспорт в этих хостах пока отсутствует. Захват экрана зависит от браузера и ОС. Реальное качество аудио/видео и работа на устройстве пока не подтверждены.

## Разметка интерфейса

В Q.Sock.UI/Views находятся пары .xaml / .xaml.cs: LoginView (вход), WorkspaceView (общая компоновка), SettingsView (аккаунты, оформление и устройства), AppearanceView (цвета темы). Визуальные стили — MessengerStyles.xaml. Состояние полей и команды форм находятся в ViewModels; подключение к серверу и операции сохраняет MessengerView. В предпросмотре отдельные представления используют стандартную тему и не обращаются к серверу.

Динамические сообщения, Markdown, звонки и элементы загружаемых плагинов продолжают создаваться на C#. Адаптивное переключение панелей находится в WorkspaceView.xaml.cs; данные списков настроек поступают через коллекции и шаблоны XAML. Привязки компилируются, расширение файлов остаётся .xaml, как в исходном шаблоне.
