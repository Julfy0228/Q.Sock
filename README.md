# Q.Sock

Кросс-платформенный мессенджер: ASP.NET Core, SignalR, EF Core / SQLite и Avalonia. Браузерный клиент тоже использует Avalonia через WebAssembly. WebRTC работает через небольшой JavaScript-мост к браузерным средствам связи.

На выходе три продукта: обычный сервер со встроенным браузерным клиентом и поддержкой расширений; один универсальный клиент для компьютера и Android; Moodle-пакет с тем же встроенным сервером, браузерным клиентом и учебными расширениями. Базовый экран входа запрашивает адрес сервера, логин и пароль. Учебные действия поступают только из загруженного расширения.

## Структура

| Проект | Назначение |
| --- | --- |
| Q.Sock.Shared | Общие контракты API |
| Q.Sock.Core | Подключение, авторизация, SignalR, темы, Markdown, проверка пакетов |
| Q.Sock.UI | Общий адаптивный интерфейс |
| Q.Sock.PluginContracts | Контракт загружаемых модулей интерфейса |
| Q.Sock.Client | Настольный клиент |
| Q.Sock.Android | Android-клиент, защищённое хранение сессий |
| Q.Sock.Browser | Браузерный хост общего интерфейса |
| Q.Sock.Plugins.Moodle | Отдельный модуль интерфейса занятий |
| Q.Sock.Media.Web | WebRTC и работа с медиаустройствами |
| Q.Sock.Server | Универсальный сервер и загрузчик серверных расширений |
| Q.Sock.Server.Plugins.Moodle | Вход через Moodle, синхронизация курсов, занятия и отдельный контекст данных |
| integrations/moodle | Локальный плагин Moodle и элемент курса |

Модули интерфейса скачиваются с выбранного сервера и кэшируются отдельно от клиента. Первый запуск требует доверия к ключу издателя. Хеш и подпись проверяются до загрузки; механизм и упаковка описаны в [документации модулей](docs/plugins.md).

## Возможности текущей версии

Личные и групповые чаты, пространства с каналами и голосовыми комнатами, друзья и поиск пользователей, вложения и просмотр исходного кода, Markdown. Material Icons используются только в интерфейсе; преобразование смайликов и коротких кодов в сообщениях отключено. Аватарки без фотографии получают стабильный цвет из палитры 32 оттенков по ID и типу сущности. Личный чат уникален для пары пользователей; выбор получателей звонка появляется в групповых чатах. В голосовую комнату входят без рассылки вызова.

Роли, локальные ограничения сообщений, голоса, подключения и демонстрации экрана, завершение сессий устройств, политика сервера, журнал и экспорт SQLite. В учебных пространствах состав, роли и группы приходят из Moodle; местные ограничения не меняют Moodle. Можно планировать занятия, публиковать их в календаре и открывать мессенджер кнопкой курса. См. [инструкцию Moodle](docs/moodle.md).

Темы хранятся локально, редактируются, импортируются из файла или изображения QR и экспортируются в файл / QR. Сканирование QR камерой реализовано в браузере при наличии BarcodeDetector; в остальных случаях используется изображение. Разные серверы и аккаунты доступны в настольном и Android-клиентах. Браузер привязан к своему серверу.

## Локальный запуск

Нужны .NET 10 SDK и wasm-tools. Для Android дополнительно нужны workload android, Android SDK с API 36 и совместимый JDK. В этой рабочей копии подготовлен отдельный SDK `artifacts/dotnet/dotnet.exe` версии 10.0.402; системный SDK не заменялся.

Из корня репозитория:

```powershell
dotnet workload install wasm-tools
./build/Build-Browser.ps1
$env:ConnectionStrings__ChatDatabase = 'Data Source=development.db'
$env:Bootstrap__AdminUser = 'Administrator'
$env:Bootstrap__AdminPassword = 'your-local-password'
dotnet run --project Q.Sock.Server --urls http://127.0.0.1:5210
```

Браузер: http://127.0.0.1:5210/avalonia/index.html. Адрес `/` ведёт туда же. Во втором терминале:

```powershell
dotnet run --project Q.Sock.Client
```

Visual Studio для запуска не требуется. Адрес сервера настольного клиента указывается в форме входа. Для удалённого сервера необходим HTTPS. В текущем тестовом стенде используется отдельная база `artifacts/test-chat.db`, пользователь `TestAdmin`, пароль `test-only-Password49`. Это реквизиты только локального стенда.

При недоступном системном хранилище Windows вход продолжает работать до закрытия приложения; клиент показывает, что сеанс не сохранён. Токены остаются только в памяти. Для отдельного тестового профиля можно задать QSOCK_PROFILE_DIRECTORY; основной список аккаунтов и настройки не используются.

В ограниченной среде Windows можно передать скрипту браузера `-InProcessWasmTasks` и `-Dotnet ./artifacts/dotnet/dotnet.exe`. Это меняет запуск задач сборки, а не поведение приложения.

## Сборка и поставка

```powershell
./build/Publish-Server.ps1
./build/Package-Moodle.ps1
dotnet build Q.Sock.Android
```

Серверный пакет: `artifacts/server`, архивы Moodle: `artifacts/packages`, отладочный APK: `Q.Sock.Android/bin/Debug/net10.0-android`. APK содержит ARM64 и x64, минимум Android 7.0 / API 24. Для распространения нужен собственный ключ подписи; текущий APK подписан отладочным ключом.

Если Android SDK/JDK не обнаруживаются автоматически, передайте пути параметрами AndroidSdkDirectory и JavaSdkDirectory. Android вынесен из основной Q.Sock.slnx, чтобы серверная и настольная разработка не требовала мобильного workload.

## Размещение

Скопируйте deployment/.env.example в deployment/.env, задайте собственный пароль и запустите:

```powershell
docker compose --project-directory deployment -f deployment/compose.yml up --build -d
```

Шаблон публикует сервер на 127.0.0.1:8080. Для внешнего доступа нужен HTTPS-прокси с WebSocket. База, вложения и ключи находятся в отдельных томах. Dockerfile и Compose подготовлены, но Docker-сборка в этой среде не запускалась: движок недоступен.

Дополнительная конфигурация читается из Q.Sock.Server/appsettings.Local.json; переменные окружения и аргументы имеют приоритет. Пример Moodle / ICE находится в deployment/appsettings.moodle.example.json. Локальный файл с секретами исключён из Git. Сервер создаёт JWT-ключ и ключи Data Protection в state; каталог нужно сохранять между перезапусками.

Для разных сетей настройте собственные STUN/TURN в WebRtc:IceServers. Автоматической настройки TURN нет. Медиа идёт между браузерами, сервер маршрутизирует сигналы. Текущая конфигурация ограничивает звонок 12 подключениями; для полноразмерных занятий нужен отдельный SFU и реализация соответствующего транспорта.

Экспорт админ-панели содержит SQLite-базу. Вложения и state сохраняются отдельно. Восстановление выполняется на остановленном сервере после проверки копии.

## Проверка и ограничения

Воспроизводимая проверка на новых изолированных базах:

```powershell
python tests/run_checks.py
```

При уже собранных проектах добавьте --no-build. Параметр --dotnet позволяет указать отдельный SDK. Проверка поднимает собственные серверы на свободных локальных портах, выполняет шесть наборов, проверяет выдачу подписанных модулей, вход через HTTP-стенд Moodle, целостность экспорта SQLite, подпись обратного календарного запроса и весь каталог Material Icons с рендерингом. Настоящий Moodle этим не заменяется.

tests/serve_browser_checks.py запускает на 127.0.0.1:5213 отдельную страницу проверки WebRTC и IndexedDB. Она использует синтетические источники без камеры, микрофона, захвата экрана и звука из динамиков. После перезагрузки повторный запуск проверяет сохранение пакета в IndexedDB.

См. [фактические проверки](docs/verification.md) и [состояние модулей](docs/plugins.md). На Android и настольном клиенте звонок сейчас открывает браузерный Avalonia-экран с одноразовым входом. Нативный медиатранспорт в этих хостах пока отсутствует. Захват экрана зависит от браузера и ОС. Реальное качество аудио/видео и работа на устройстве пока не подтверждены.


## Три поставки

`build/Publish-Server.ps1` собирает обычный сервер и общий браузерный клиент в `artifacts/products/server`.
`build/Publish-Client.ps1` собирает универсальный настольный клиент в `artifacts/products/client`; APK находится в подпапке android после Android-сборки.
`build/Package-Moodle.ps1 -Runtime win-x64` создаёт Moodle-комплект со встроенным сервером и расширениями в `artifacts/products/moodle`. Для Linux доступны параметры linux-x64/linux-arm64.

Список требований из исходного большого сообщения и уточнений сохранён в docs/requirements.md. Проверки и оставшиеся ограничения — docs/verification.md и IMPLEMENTATION.md.
